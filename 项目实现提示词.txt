# 心率监测系统项目实现提示词

## 1. 项目背景与目标

### 1.1 项目背景
- 随着健康监测技术的发展，非接触式心率监测成为可能
- 传统心率监测需要佩戴设备，使用不便且可能影响用户体验
- 基于摄像头的心率监测技术利用光电容积脉搏波（rPPG）原理，可实现无接触式监测

### 1.2 项目目标
- 开发一套基于Web的实时心率监测系统，使用设备摄像头或ESP32摄像头
- 实现人脸检测与跟踪，确保心率监测的准确性
- 提供直观的数据可视化界面，显示实时心率和信号波形
- 支持数据存储与历史记录查询
- 确保系统在不同设备和网络环境下的稳定性和可靠性

## 2. 核心功能需求

### 2.1 视频捕获与处理
- **多摄像头支持**：支持设备内置摄像头和ESP32网络摄像头
- **实时视频流**：30fps的视频捕获和处理速度
- **高分辨率支持**：兼容720p、1080p分辨率
- **视频质量保证**：确保原始视频质量不被处理过程影响

### 2.2 人脸检测与跟踪
- **高精度检测**：95%+的人脸检测准确率
- **多人脸支持**：能够同时检测和跟踪多张人脸
- **实时跟踪**：<100ms的延迟，确保矩形框实时跟随人脸
- **边界框绘制**：红色矩形框，2px线宽，清晰可见
- **坐标转换**：确保矩形框在不同分辨率下的准确位置
- **误报过滤**：减少非人脸区域的误检测

### 2.3 心率监测
- **rPPG分析**：基于人脸区域的光电容积脉搏波分析
- **实时计算**：每帧实时计算心率，更新频率≥1Hz
- **信号处理**：噪声过滤、信号增强等预处理
- **心率范围**：支持60-200BPM的心率范围
- **数据准确性**：心率测量误差≤5BPM

### 2.4 数据可视化
- **实时心率显示**：大字体显示当前心率值
- **信号波形图**：ECG风格的心率信号波形
- **统计数据**：显示平均、最小、最大心率值
- **历史记录**：保存并显示历史心率测量结果
- **响应式设计**：适配不同屏幕尺寸

### 2.5 系统控制
- **开始/停止监测**：用户可控制监测过程
- **数据保存**：支持将当前心率数据保存到服务器
- **摄像头选择**：可切换设备摄像头或ESP32摄像头
- **状态管理**：清晰的系统状态指示

### 2.6 网络通信
- **WebSocket**：实时双向通信，低延迟
- **数据压缩**：优化视频数据传输效率
- **错误处理**：网络中断自动重连机制
- **状态同步**：确保前后端状态一致

## 3. 技术栈与架构要求

### 3.1 前端技术栈
- **HTML5/CSS3**：页面结构和样式
- **JavaScript (ES6+)**：前端逻辑实现
- **Canvas API**：视频捕获和图像处理
- **WebSocket API**：实时通信
- **Responsive Design**：响应式布局

### 3.2 后端技术栈
- **Python 3.8+**：后端开发语言
- **FastAPI**：Web框架，支持WebSocket
- **OpenCV**：计算机视觉库，用于人脸检测
- **NumPy**：数值计算库，用于信号处理
- **uvicorn**：ASGI服务器
- **rPPG算法**：心率监测核心算法

### 3.3 架构设计
- **前后端分离**：前端负责UI和用户交互，后端负责数据处理
- **WebSocket通信**：实时视频流和心率数据传输
- **模块化设计**：
  - 前端：CameraManager、WebSocketManager、UIManager
  - 后端：FaceRecognitionService、RPPGService、WebSocketManager
- **数据流**：
  1. 前端捕获视频帧 → 转换为base64 → 通过WebSocket发送
  2. 后端接收数据 → 解码图像 → 人脸检测 → rPPG分析 → 计算心率
  3. 后端返回心率数据和人脸坐标 → 前端更新UI和绘制矩形框

## 4. 开发规范与标准

### 4.1 代码规范
- **前端**：遵循ESLint标准，使用2空格缩进，驼峰命名法
- **后端**：遵循PEP 8规范，4空格缩进，清晰的函数和变量命名
- **注释要求**：关键代码段必须有详细注释，函数必须有文档字符串

### 4.2 性能标准
- **前端**：
  - 视频捕获和处理延迟 < 100ms
  - 页面加载时间 < 2s
  - 内存使用优化，避免内存泄漏
- **后端**：
  - 单帧处理时间 < 33ms（30fps）
  - WebSocket响应时间 < 50ms
  - 支持并发连接数 ≥ 10

### 4.3 兼容性要求
- **浏览器兼容**：支持Chrome、Firefox、Safari、Edge最新版本
- **设备兼容**：支持桌面端和移动端设备
- **分辨率兼容**：适配720p、1080p、4K等不同分辨率
- **网络兼容**：在2Mbps以上网络环境下正常运行

### 4.4 安全标准
- **数据传输**：使用WebSocket Secure (WSS) 加密传输
- **输入验证**：前端和后端双重验证，防止恶意输入
- **资源限制**：限制视频帧大小和频率，防止DoS攻击
- **错误处理**：优雅处理错误，避免信息泄露

## 8. 开发建议与注意事项

### 8.1 技术实现建议
- **前端**：使用requestAnimationFrame优化渲染性能，使用Promise和async/await处理异步操作
- **后端**：使用多线程处理视频帧，使用缓存优化频繁访问的数据
- **WebSocket**：实现心跳机制确保连接稳定，使用二进制数据传输提高效率

### 8.2 常见问题与解决方案
- **人脸检测误报**：调整OpenCV参数，使用多通道检测和去重逻辑
- **心率计算不准确**：优化rPPG算法，增强信号预处理
- **网络延迟**：使用数据压缩，调整视频质量和分辨率
- **内存泄漏**：及时释放资源，使用WeakMap管理对象引用

### 8.3 最佳实践
- **模块化开发**：将功能拆分为独立模块，便于测试和维护
- **增量开发**：从核心功能开始，逐步添加高级特性
- **持续测试**：开发过程中不断测试，及时发现和解决问题
