## ESP32-S3-EYE 摄像头 OV3660 修复总结

### 问题现象
程序在启动过程中大部分步骤都成功了，但在捕获摄像头图像环节失败，反复打印以下错误：
```
cam_hal: NO-SOI - JPEG start marker missing
W (47057) cam_hal: Failed to get frame: timeout
E (47057) camera: Failed to acquire frame
E (63557) camera: Failed to acquire valid JPEG frame after 5 retries
```

### 问题根源
1. **摄像头型号识别错误**：ESP32 实际识别到的是 OV3660 摄像头，而非预期的 OV5640
2. **引脚配置错误**：当前引脚定义与 ESP32-S3-EYE 官方文档中的 OV3660 引脚配置不符
3. **配置参数不匹配**：XCLK 频率、帧大小、质量等参数不适合 OV3660 摄像头
4. **电源和复位引脚未正确配置**：PWDN 和 RESET 引脚被设置为 -1（未使用），但实际上 OV3660 需要这两个引脚

### 修复方案
修改了 `camera.c` 文件，全面更新摄像头配置以适配 OV3660 摄像头：

1. **更新引脚定义**：
   - 从官方文档获取了 ESP32-S3-EYE OV3660 的正确引脚配置
   - 设置了正确的 PWDN (GPIO6) 和 RESET (GPIO7) 引脚
   - 更新了 D0-D7 数据线和其他控制引脚

2. **优化摄像头配置**：
   - XCLK 频率从 10MHz 改为 20MHz（适合 OV3660）
   - 帧大小从 VGA (640x480) 改为 QVGA (320x240)（提高稳定性）
   - JPEG 质量从 30 改为 40（平衡质量和速度）
   - 帧缓冲区位置从 DRAM 改为 PSRAM（OV3660 需要更多内存）

3. **更新传感器设置**：
   - 调整帧大小和质量参数，使其与配置匹配
   - 关闭图像翻转和镜像（OV3660 不需要）
   - 初始化延迟从 1 秒改为 2 秒（给 OV3660 足够的稳定时间）

### 修复后的关键代码

**引脚定义**：
```c
// ESP32-S3-EYE camera pins configuration (correct for OV3660)
#define CAM_PIN_PWDN    6   // Power down is used (GPIO6, low active)
#define CAM_PIN_RESET   7   // Reset pin is used (GPIO7, low active)
#define CAM_PIN_XCLK    15
#define CAM_PIN_SIOD    4
#define CAM_PIN_SIOC    5

#define CAM_PIN_D7      19
#define CAM_PIN_D6      17
#define CAM_PIN_D5      18
#define CAM_PIN_D4      12
#define CAM_PIN_D3      10
#define CAM_PIN_D2      8
#define CAM_PIN_D1      9
#define CAM_PIN_D0      11
#define CAM_PIN_VSYNC   16
#define CAM_PIN_HREF    14
#define CAM_PIN_PCLK    13
```

**摄像头配置**：
```c
.xclk_freq_hz = 20000000,          // XCLK 20MHz for OV3660
.frame_size = FRAMESIZE_QVGA,       // 320x240 resolution
.jpeg_quality = 40,                 // JPEG quality 40
.fb_location = CAMERA_FB_IN_PSRAM,  // Use PSRAM for frame buffer
```

**传感器设置**：
```c
// Set sensor parameters for better performance (OV3660 specific)
sensor->set_pixformat(sensor, PIXFORMAT_JPEG);
sensor->set_framesize(sensor, FRAMESIZE_QVGA);
sensor->set_quality(sensor, 40);
sensor->set_vflip(sensor, 0);
sensor->set_hmirror(sensor, 0);
vTaskDelay(pdMS_TO_TICKS(2000)); // Longer delay for OV3660 initialization
```

### 编译和烧录步骤
1. 进入 ESP32 项目目录：
   ```bash
   cd ~/esp32-camera
   ```

2. 清理之前的构建文件：
   ```bash
   idf.py clean
   ```

3. 编译项目：
   ```bash
   idf.py build
   ```

4. 烧录到设备：
   ```bash
   idf.py flash -p /dev/ttyUSB0
   ```

5. 查看串口输出：
   ```bash
   idf.py monitor -p /dev/ttyUSB0
   ```

### 测试建议
1. 烧录完成后，等待设备启动并连接到 WiFi
2. 在串口输出中查找设备获取的 IP 地址（例如：`got ip:192.168.2.197`）
3. 在浏览器中访问 `http://<设备IP>`，查看摄像头实时流
4. 在浏览器中访问 `http://<设备IP>/stream`，直接查看 MJPEG 流
5. 在心率监测系统前端，选择 "ESP32摄像头" 模式，输入设备 IP 地址，点击 "开始监测"

### 预期结果
修复后，串口日志中的 JPEG 错误应该会消失，摄像头能够稳定输出 MJPEG 视频流，浏览器和心率监测系统都能正常显示视频画面。
