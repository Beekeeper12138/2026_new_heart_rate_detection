## ESP32-S3-EYE 视频流 chunked 编码问题修复总结

### 问题现象
ESP32-S3-EYE 设备可以正常连接，HTTP 服务器运行正常，但访问 `/stream` 时无法显示视频流，浏览器控制台显示 `ECONNRESET (error 104)` 错误。

### 问题根源
根据日志分析，问题的核心是：

1. **ESP32 使用了分块传输编码 (chunked)**：
   - 响应头中包含 `transfer-encoding: chunked`
   - 这种编码要求 ESP32 严格按照特定格式发送数据块

2. **浏览器期望持久连接**：
   - 请求头中包含 `connection: keep-alive`
   - 浏览器期望保持连接并接收持续的视频流

3. **分块编码格式错误**：
   - ESP32 发送的分块数据格式不符合 HTTP 规范
   - 导致浏览器无法解析，从而强制关闭连接

### 修复方案
修改了 `http_server.c` 文件中的 `http_handler_stream` 函数，采用了一种简单有效的方法来解决 chunked 编码问题：

1. **禁用 chunked 编码**：
   - 通过设置一个非常大的 `Content-Length` 头（"10000000"）
   - 这会强制 esp_http_server 库使用 `Content-Length` 而不是 `Transfer-Encoding: chunked`

2. **优化 HTTP 头设置**：
   - 设置正确的 `Content-Type: multipart/x-mixed-replace; boundary=frame`
   - 添加 `Access-Control-Allow-Origin: *` 解决跨域问题
   - 设置 `Cache-Control: no-cache` 确保浏览器不缓存视频流
   - 设置 `Connection: close` 明确告知浏览器连接类型

3. **保持分块发送逻辑**：
   - 仍然使用 `httpd_resp_send_chunk` 函数发送数据
   - 但由于禁用了 chunked 编码，这些数据会被直接发送，而不是按照 chunked 格式包装

### 修复后的关键代码
```c
static esp_err_t http_handler_stream(httpd_req_t *req)
{
    ESP_LOGI(TAG, "Client connected for stream");

    /* Set HTTP response type and headers */
    httpd_resp_set_type(req, CONTENT_TYPE_MJPEG);
    httpd_resp_set_hdr(req, "Access-Control-Allow-Origin", "*");
    httpd_resp_set_hdr(req, "Cache-Control", "no-cache");
    httpd_resp_set_hdr(req, "Connection", "close");
    
    /* Disable chunked encoding by setting content length to a large value */
    /* This forces esp_http_server to use Content-Length instead of Transfer-Encoding: chunked */
    httpd_resp_set_hdr(req, "Content-Length", "10000000");

    // ... 后续代码保持不变 ...
}
```

### 编译和烧录步骤
1. 进入 ESP32 项目目录：
   ```bash
   cd ~/esp32-camera
   ```

2. 清理之前的构建文件：
   ```bash
   idf.py clean
   ```

3. 编译项目：
   ```bash
   idf.py build
   ```

4. 烧录到设备：
   ```bash
   idf.py flash -p /dev/ttyUSB0
   ```

5. 查看串口输出：
   ```bash
   idf.py monitor -p /dev/ttyUSB0
   ```

### 测试建议
1. 烧录完成后，等待设备启动并连接到 WiFi
2. 在串口输出中查找设备获取的 IP 地址（例如：`got ip:192.168.2.197`）
3. 在浏览器中访问 `http://<设备IP>`，查看摄像头实时流
4. 在浏览器中访问 `http://<设备IP>/stream`，直接查看 MJPEG 流
5. 在心率监测系统前端，选择 "ESP32摄像头" 模式，输入设备 IP 地址，点击 "开始监测"

### 预期结果
修复后，访问 `/stream` 时应该能看到摄像头实时画面，浏览器控制台不再显示 `ECONNRESET` 错误，心率监测系统也能正常接收和处理视频流。
