# 视频流清晰度下降原因分析

## 主要原因

1. **双重图像压缩**：
   - 前端捕获时使用 `canvas.toDataURL('image/jpeg', 0.7)` (70% 质量)
   - 后端编码时使用 `image.save(buffer, format='JPEG', quality=85)` (85% 质量)
   - 双重压缩导致图像质量显著下降

2. **分辨率限制**：
   - 前端设备摄像头设置为 640x480 理想分辨率
   - 可能未充分利用摄像头的最大分辨率

3. **传输带宽影响**：
   - 高分辨率图像通过 WebSocket 传输时可能受到带宽限制
   - 导致传输延迟或需要进一步压缩

4. **图像处理效率**：
   - 虽然人脸检测使用了缩小的帧，但最终编码和传输的是原始分辨率图像

# 优化方案

## 1. 提高前端捕获质量
- 修改 `camera.js` 中的 `getFrame()` 方法，将 JPEG 质量从 0.7 提高到 0.95
- 增加摄像头分辨率设置，使用更高的理想分辨率

## 2. 优化后端编码参数
- 修改 `face_recognition.py` 中的 `encode_image()` 方法，将 JPEG 质量从 85 提高到 95
- 考虑使用 PNG 格式进行编码，避免有损压缩

## 3. 调整传输策略
- 实现自适应质量调整，根据网络带宽动态调整压缩质量
- 考虑使用 WebRTC 替代 WebSocket 进行视频流传输，提高传输效率

## 4. 优化前端显示
- 确保 `processed-image` 元素正确显示图像，避免拉伸或压缩
- 实现响应式显示，根据容器大小调整图像显示尺寸

## 5. 性能优化
- 保持人脸检测的帧缩小策略，确保实时性
- 优化图像处理算法，减少处理时间

## 实施步骤

1. **修改前端代码**：
   - 提高 `getFrame()` 方法中的 JPEG 质量参数
   - 调整摄像头分辨率设置

2. **修改后端代码**：
   - 提高 `encode_image()` 方法中的 JPEG 质量参数
   - 添加 PNG 编码选项

3. **测试和优化**：
   - 测试不同质量参数下的图像清晰度和传输性能
   - 根据测试结果调整最佳参数组合

4. **验证功能**：
   - 确保矩形框功能正常运行
   - 验证多人人脸检测和不同分辨率视频的兼容性

通过这些优化措施，预计可以显著提高视频流清晰度，同时保持矩形框功能的正常运行。
